# Build and release

How to get from a fresh clone to a running game, a debug APK, a signed release AAB and the web build. It describes the repo as it is. `CLAUDE.md` holds the rules; `docs/release-checklist.md` is the per-release checklist this page points to; `docs/platform-update.md` is the yearly Android procedure.

There is **no voice or narration pipeline** (Spiro, 2026-10-19): the game has no spoken audio, so nothing here regenerates audio. Art is drawn in code, music and sound effects are generated by the scripts in `tools/music/` and `tools/sfx/`.

## 1. Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Godot | the version in `.godot-version` (4.7.2-stable), standard build, not .NET | Set `GODOT` to the executable, e.g. `export GODOT="/c/Tools/Godot/Godot_v4.7.2-stable_win64_console.exe"`. Do not upgrade without asking Spiro. |
| Export templates | the same version | Needed for any export. Godot: Editor > Manage Export Templates, or unpack the `.tpz` into `~/.local/share/godot/export_templates/4.7.2.stable/` (Linux). CI does the latter. |
| JDK | 17 (Temurin) | Android only. |
| Android SDK | platform and build-tools for the target SDK in `.android-target-sdk` (36) | Android only. Set the SDK and JDK paths in Godot's editor settings. |
| Python | 3.12 | `pip install -r tools/requirements.txt` (pytest). Handwriting training also needs `tools/handwriting/requirements.txt`; it is build time only. |
| adb | any recent | Installing the debug APK. |

The shell commands work in Git Bash on Windows (the developer machine) and on Linux.

## 2. Fresh clone to running game

```bash
git clone <repo> && cd Gem-Mines-of-Number-Mountain
"$GODOT" --headless --path . --import             # first import; needed before any headless run
"$GODOT" --path .                                  # run the game in the editor's runtime
GODOT_BIN="$GODOT" ./addons/gdUnit4/runtest.sh --headless --ignoreHeadlessMode -c -a res://tests
python -m pytest tools
python tools/ci/lint_content.py
```

`-c` keeps going after a failure (without it a suite stops at its first failing test). To run one suite: `-a res://tests/generators/test_place_value.gd`. Parallel Godot runs on one machine share `user://`; give each its own `XDG_DATA_HOME`, and never run two `--import` runs at once in the same folder.

The other checks (see the release checklist section 2): `python tools/crosscheck/run.py --all --n 10000` (needs `GODOT`), `python tools/ci/curriculum_check.py`, `python tools/ci/perf_check.py`, `python tools/ci/check_sdk_audit.py`. Mouse-only play: `"$GODOT" --path . -- --no-touch`.

## 3. Debug APK and install

```bash
mkdir -p build
"$GODOT" --headless --path . --install-android-build-template --export-debug "Android" build/gem-mines-debug.apk
adb install -r build/gem-mines-debug.apk
```

`--install-android-build-template` puts the Gradle template in `android/build/` (gitignored). Godot 4.7.2 can exit with a non-zero status right after writing the APK; CI therefore checks the file (`test -s`, `classes.dex` present) rather than the exit code. Check the permissions of what you built:

```bash
AAPT2="$ANDROID_SDK_ROOT/build-tools/36.0.0/aapt2" python tools/ci/check_manifest.py build/gem-mines-debug.apk
```

CI builds a debug APK with a throwaway keystore on every merge to `main` (`.github/workflows/ci.yml`, job `android-debug`) and uploads it as an artifact.

## 4. Release AAB for Google Play

Follow `docs/release-checklist.md` in order. In short:

1. **Spiro** raises `version/code` (always above the last upload) and sets `version/name` in **both** Android presets. Agents do not change export settings.
2. Release keystore only in environment variables: `GODOT_ANDROID_KEYSTORE_RELEASE_PATH`, `_USER`, `_PASSWORD`. Never in the repo.
3. `"$GODOT" --headless --path . --export-release "Android AAB" build/gem-mines.aab`, then `python tools/ci/check_manifest.py build/gem-mines.aab` (no `INTERNET`, location, camera, microphone, contacts or ad ID; phones not shut out).
4. Record the SHA-256 and the commit, outside the repo. Upload to the **internal testing** track in Play Console, run the device passes, then promote (closed test, then production with a staged rollout).

The shipped game never asks for the network (rule 1): `permissions/internet=false` in both Android presets (the Web preset has no permission keys; nothing in it may turn one on), enforced by `tools/ci/test_export_presets.py`.

## 5. Web build and GitHub Pages

The Web preset is single-threaded (`variant/thread_support=false`), so it needs no cross-origin isolation headers and GitHub Pages can host it with no extra code or service worker. Decision and alternatives: `docs/decisions.md`, Phase 5 web export entry.

```bash
mkdir -p build/web
"$GODOT" --headless --path . --export-release "Web" build/web/index.html
cp tools/web/about.html build/web/about.html
python tools/web/render_policy.py docs/privacy-policy.md build/web/privacy-policy.html
python -m http.server --directory build/web 8000     # then open http://localhost:8000 in Chrome
```

`.github/workflows/web-deploy.yml` exports the preset on every push to `main` (export and size check only) and publishes `build/web/` to GitHub Pages when a tag `v*` is pushed (enable Pages with source "GitHub Actions" once in the repository settings). It uses only `actions/checkout`, `actions/upload-pages-artifact` and `actions/deploy-pages`. Size budget: under 150 MB (the 4.7.2 build measured about 43 MB).

Web differences: `user://` is the browser's IndexedDB, so saves survive a reload but not "clear site data"; the `NOTIFICATION_WM_CLOSE_REQUEST` save may not fire, so the per-rock save point carries the load; handwriting recognition is plain GDScript, so the `ChalkSlate` works on web where the browser reports a touch screen, and the `NumberPad` appears otherwise (the existing no-touch fallback); these are manual checks; the parent dashboard shows a note instead of Export and Import on web (`DashboardScreen.is_web()`), because Godot's file dialog on web cannot reach the computer's disk (a download through `JavaScriptBridge.download_buffer` would be new code; not built).

### Web smoke checklist (manual; no browser automation is installed)

- [ ] `index.html` loads in Chrome on a Chromebook; no console errors.
- [ ] DevTools > Network: after the first load, **no further requests** while playing.
- [ ] A Zone 1 rock completes by touch and by mouse; sounds start after the first tap or click.
- [ ] Reload: progress, profile and settings are still there.
- [ ] With a mouse the number pad appears; with touch the slate works and answers read correctly.
- [ ] Scholar mode: keyboard entry works with a physical keyboard.
- [ ] `about.html` and `privacy-policy.html` open.

## 6. Generated assets

- Music: `python tools/music/generate_placeholder_music.py` (all) or `--track mine_z11` (one). Sound effects: `python tools/sfx/generate_placeholder_sfx.py`. Output is OGG under `assets/`; every file needs a row in `assets/CREDITS.md` (lint rule 10).
- Handwriting network: `python tools/handwriting/train.py`, then `make_fixtures.py` (see `CLAUDE.md`).
- Store graphics: `marketing/render.sh`.
- Screenshots for review: `xvfb-run -a "$GODOT" --path . --rendering-driver opengl3 res://tools/qa/capture_screens.tscn`.

## 7. Yearly target-API update

`docs/platform-update.md` is the full procedure. Summary: check Play's new requirement in July, stay on Godot 4.7.x unless it cannot target the SDK (ask Spiro first), bump `.android-target-sdk`, `gradle_build/target_sdk` in both presets and the CI SDK packages in one commit, rerun the full regression, then release as a maintenance update.

## 8. Rollback

Play Console cannot delete an uploaded version code. To roll back, take the last good AAB's source tag, **raise** `version/code` above the bad build, rebuild and upload it as a new release (staged), or halt the bad rollout in Play Console first. For the web, re-run the Pages deploy from the last good tag (Actions > the tag's run > re-run), or push a new tag from the good commit.

## 9. Maintenance cadence (after Version 2.0)

Monthly (about a day): run all tests and lint on `main`; export play logs from the parent area on Spiro's own devices only (`private/` is gitignored and never uploaded); run `python tools/bkt/fit.py` and propose any BKT changes in `docs/decisions.md` (apply only with sign-off). Quarterly: check the Godot 4.7.x release notes (upgrade only on purpose and after asking), rerun `docs/compliance/families-self-check.md`. Yearly (August): section 7. Nothing in maintenance mode may add network access, SDKs or data collection.
