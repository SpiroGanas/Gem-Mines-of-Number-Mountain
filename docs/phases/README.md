# Phase plans

Five implementation plans, one per phase of `../development-plan.md`. Each uses the same section order (Overview, Entry criteria, Architecture and design, Sprint plan, Testing and quality, Exit criteria, Risks, Decisions for Spiro, Hand-off) and the same backlog-table columns (`ID | Branch | Item | Done when`). Backlog IDs are `P<phase>-S<sprint>-<nn>`.

| Phase | File | Sprints | Status |
|---|---|---|---|
| 1. Ramp-up to MVP | [`phase-1-ramp-up-to-mvp.md`](phase-1-ramp-up-to-mvp.md) | 1–11 | Committed |
| 2. Version 1.0 | [`phase-2-version-1-0.md`](phase-2-version-1-0.md) | 12–21 | Provisional (decision gate Feb 19, 2027) |
| 3. Public release readiness | [`phase-3-public-release-readiness.md`](phase-3-public-release-readiness.md) | 22–28 | Provisional |
| 4. Middle mountain | [`phase-4-middle-mountain.md`](phase-4-middle-mountain.md) | 29–40 | Provisional |
| 5. Deep mountain | [`phase-5-deep-mountain.md`](phase-5-deep-mountain.md) | 41–52 | Provisional |

Skill IDs for Zones 1–3 are defined in the Phase 1 plan; later phases reference them and define their own zones' IDs. When a shipped `curriculum/skills/*.json` file differs from a plan document, the shipped file wins and the plan should be updated.
